## rubik_cube_core

ルービックキューブを解くためのプログラム.

別プロセスとして起動し，Socket通信によって外部プログラムから利用する.
- デフォルト 127.0.0.1:8080
- 転送データはsocket_server.cpp:32を参照

特徴
- IDA*による高速な探索
- 探索を2段階に分け，メモリ使用量を削減
- 対面同時操作を考慮
- 許容解の長さ指定

2023からの変更点
- PythonからC++に変更し高速化
    - テーブル生成が約300倍の高速化(90s->300ms)
    - 18手以内の解の探索が約100倍の高速化(985ms->10.4ms)

## rubik_solver_ev3_server/main.py

EV3の各モータ、センサを動作させるプログラムです.

要設定パラメータ
- 45行目 M_maxspeed Mモータ(アームを回す)の速度,上限は1560
- 46行目 L_maxspeed Lモータ(アームの離す・掴む)の速度,上限は1050
- 47行目 L_maxpos Lモータのアームを離すための回転角度の設定
- 48行目 L_minpos Lモータのアームを掴むための回転角度の設定
- 49行目 rotate_90 アームを90度回すのに必要なモータの回転角度 
- 50行目 cs_red アームの位置を補正する際に使用する赤い棒を認識するためのカラーセンサのしきい値

細かい内容はプログラム中のコメントに書いてます.

## 起動方法

1. EV3本体をすべて起動
2. EV3，カメラをPCに接続
3. Logicoolカメラ設定で必要に応じてカメラの調整
3. ターミナルを2つ開きそれぞれでプログラムを起動
```bash
ターミナル1
> cd rubik_cube_core
> ./main.exe
```
```bash
ターミナル1
> cd rubik_cube_main
// ターミナル1でSetup Finishの出力を確認した後に実行
> python ..\rubiks_solver_main.py
```

## ロボットの操作方法

PC側

GUI上のStatusによって可能な操作が異なる
- Status -> かStatus -> Finish ! の場合
    - Spaceキー：待機状態(Status -> Waiting ...)へ移行
    - uキー：リフトの上昇(すでに上にある場合は押さないこと！)
    - dキー：リフトの下降(すでに下にある場合は押さないこと！)
    - rキー：すべてのモータの動作，ロックの解除とエンコーダリセット
    - tキー：テスト撮影状態(Status -> Scanning ...)に移行
- Status -> Waiting ... の場合
    - タッチセンサ押下でスキャンから揃えるまでの動作開始
- Status ->Scaning ... の場合
    - Escキーで終了

## 問題発生時
- カメラ画像が更新されているが画像認識がうまくいかない場合
    - カメラの上に光を抑えるものを置くなどして光の加減を調整する
    - 各色のしきい値が適切ではない場合に発生

- カメラ画像が表示されない，カメラ画像が更新されない場合
    - ホワイトアウトのしきい値を下げる(デフォルト:100)
        - cube_config:61 fram_white
    - 画像全体の輝度平均がしきい値を上回った場合，白飛びしたと判定し次の画像を読込む処理が原因

- モータ動作中にキューブが抜けたなどして停止させる場合
    1. プログラムをCtrl+Cで停止させる(ターミナルを選択すること)
    2. USBを抜く(抜いてターミナルに戻ったものがデッドロックの原因のブロック)
    3. Port Viewで命令破棄
    4. モータの線の再接続
    5. USBをさしなおす
    6. プログラムの再実行
    - 以上で正常起動しない場合はEV3の再起動
    - PCから制御命令を送信し．EV3を介してPCが直接的にモータを制御していることが原因
    - EV3内でプログラムを実行している訳ではないので別タスクに止めてもらうしかない，戻るボタンは無意味
